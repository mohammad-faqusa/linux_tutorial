## 179. Sending Signals with the `kill` command & the Interruption Signal SIGINT

# Sending Signals with `kill` and Understanding SIGINT

The Linux command:

```bash id="’wini656"
kill
```

does NOT literally mean:

```text id="’wini657"
destroy process
```

It actually means:

```text id="’wini658"
send a signal to a process
```

Signals are lightweight messages that influence process behavior.

---

# 1. Basic `kill`

Syntax:

```bash id="’wini659"
kill PID
```

Example:

```bash id="’wini660"
kill 4211
```

This sends:

```text id="’wini661"
SIGTERM (signal 15)
```

by default.

---

# 2. Important Signals

| Signal  | Number | Purpose              |
| ------- | ------ | -------------------- |
| SIGINT  | 2      | interrupt            |
| SIGTERM | 15     | graceful termination |
| SIGKILL | 9      | force kill           |
| SIGSTOP | 19     | pause                |
| SIGCONT | 18     | continue             |

---

# 3. SIGINT — Interruption Signal

SIGINT means:

```text id="’wini662"
interrupt current execution
```

Usually generated by:

```text id="’wini663"
Ctrl + C
```

inside terminal.

---

# 4. Real Example

Run:

```bash id="’wini664"
yes
```

Terminal floods with:

```text id="’wini665"
y
```

Now press:

```text id="’wini666"
Ctrl + C
```

What happens?

Terminal sends:

```text id="’wini667"
SIGINT
```

to foreground process.

Process terminates.

---

# 5. Sending SIGINT Manually

Find PID:

```bash id="’wini668"
pgrep yes
```

Suppose:

```text id="’wini669"
619824
```

Send SIGINT manually:

```bash id="’wini670"
kill -2 619824
```

or:

```bash id="’wini671"
kill -SIGINT 619824
```

Same thing.

---

# 6. Signal Numbers vs Names

These are equivalent:

```bash id="’wini672"
kill -2 PID
```

```bash id="’wini673"
kill -SIGINT PID
```

Signal names are more readable.

---

# 7. Why SIGINT Exists

SIGINT allows user to:

```text id="’wini674"
politely interrupt interactive programs
```

Examples:

* stop infinite loops
* cancel downloads
* stop scripts
* terminate commands

---

# 8. SIGINT vs SIGTERM

---

## SIGINT

Usually:

```text id="’wini675"
user interruption
```

Typically from terminal.

---

## SIGTERM

Usually:

```text id="’wini676"
system/application shutdown request
```

More formal termination.

---

# 9. Processes Can Handle SIGINT

Programs may catch SIGINT and decide what to do.

Example:

* ask “Are you sure?”
* save work
* cleanup files

---

# 10. Example in Bash

Create script:

```bash id="’wini677"
nano test.sh
```

Content:

```bash id="’wini678"
#!/bin/bash

trap "echo SIGINT received" SIGINT

while true
do
    echo running
    sleep 1
done
```

Make executable:

```bash id="’wini679"
chmod +x test.sh
```

Run:

```bash id="’wini680"
./test.sh
```

Press:

```text id="’wini681"
Ctrl+C
```

You’ll see:

```text id="’wini682"
SIGINT received
```

because script trapped signal.

---

# 11. Foreground Processes Receive SIGINT

Important concept:

```text id="’wini683"
Ctrl+C affects foreground process group
```

NOT all system processes.

---

# 12. Process Groups

Terminal manages:

* foreground jobs
* background jobs

Signals like SIGINT usually target:

```text id="’wini684"
foreground group
```

---

# 13. Difference Between SIGINT and SIGKILL

| Signal  | Catchable? | Graceful? |
| ------- | ---------- | --------- |
| SIGINT  | yes        | yes       |
| SIGTERM | yes        | yes       |
| SIGKILL | no         | no        |

---

# 14. Why SIGKILL Is Last Resort

```bash id="’wini685"
kill -9 PID
```

Kernel destroys process immediately.

No cleanup possible.

Dangerous for:

* databases
* file writes
* transactions

---

# 15. Viewing All Signals

Run:

```bash id="’wini686"
kill -l
```

Lists all signal names.

# 17. Another Example — Sleep

Run:

```bash id="’wini690"
sleep 100
```

Interrupt with:

```text id="’wini691"
Ctrl+C
```

Terminal sends SIGINT.

---

# 18. SIGINT in Programming

Most languages support signal handling:

| Language | Signal Handling |
| -------- | --------------- |
| C        | `signal()`      |
| Python   | `signal` module |
| Java     | shutdown hooks  |
| Node.js  | `process.on()`  |

Very important in backend systems.

---

# 19. Real Backend Importance

Servers should properly handle:

* SIGINT
* SIGTERM

to:

* close connections
* save state
* stop gracefully

---

# 20. Docker and Kubernetes

Containers often receive:

* SIGTERM
* SIGINT

during shutdown/redeployment.

Backend apps must handle them correctly.
