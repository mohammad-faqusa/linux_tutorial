## 177. Influencing Processes with Signals

# Influencing Processes with Signals

Linux processes communicate using:

```text id="jlwm619"
signals
```

A signal is a small message sent to a process to influence its behavior.

Examples:

* stop process
* terminate process
* pause process
* continue process
* reload configuration

Signals are fundamental in Unix/Linux systems.

---

# 1. What Is a Signal?

A signal is:

```text id="’wini620"
an asynchronous notification sent to a process
```

Usually sent by:

* kernel
* terminal
* another process
* user commands

---

# 2. Real-Life Analogy

Imagine signals as:

| Signal       | Meaning   |
| ------------ | --------- |
| tap shoulder | pause     |
| alarm        | terminate |
| phone call   | wake up   |

Processes receive signals and react accordingly.

---

# 3. Common Signal Commands

| Command   | Purpose                   |
| --------- | ------------------------- |
| `kill`    | send signal to PID        |
| `pkill`   | send signal by name       |
| `killall` | signal all matching names |

Important:

```text id="’wini621"
kill does NOT necessarily mean terminate
```

It means:

```text id="’wini622"
send a signal
```

---

# 4. View All Signals

Run:

```bash id="’wini623"
kill -l
```

Example output:

```text id="’wini624"
1) SIGHUP
2) SIGINT
9) SIGKILL
15) SIGTERM
18) SIGCONT
19) SIGSTOP
```

---

# 5. Most Important Signals

| Signal  | Number | Meaning                 |
| ------- | ------ | ----------------------- |
| SIGTERM | 15     | graceful termination    |
| SIGKILL | 9      | force kill              |
| SIGINT  | 2      | Ctrl+C interrupt        |
| SIGSTOP | 19     | pause process           |
| SIGCONT | 18     | continue paused process |
| SIGHUP  | 1      | reload/restart behavior |

These are extremely important.

---

# 6. SIGTERM — Graceful Shutdown

Default signal for:

```bash id="’wini625"
kill PID
```

Actually means:

```bash id="’wini626"
kill -15 PID
```

or:

```bash id="’wini627"
kill -SIGTERM PID
```

---

# 7. Why SIGTERM Is Preferred

It allows process to:

* save data
* close files
* cleanup resources
* shutdown gracefully

Example:

* databases
* web servers
* Spring Boot apps

---

# 8. SIGKILL — Force Kill

```bash id="’wini628"
kill -9 PID
```

or:

```bash id="’wini629"
kill -SIGKILL PID
```

Kernel immediately destroys process.

Process CANNOT ignore it.

---

# 9. Why SIGKILL Is Dangerous

Process gets NO cleanup chance.

Possible problems:

* corrupted files
* incomplete writes
* database corruption
* resource leaks

Use only when necessary.

---

# 10. SIGINT — Interrupt

Generated by:

```text id="’wini630"
Ctrl + C
```

in terminal.

Example:

```bash id="’wini631"
yes
```

Press:

```text id="’wini632"
Ctrl+C
```

Terminal sends:

```text id="’wini633"
SIGINT
```

---

# 11. SIGSTOP — Pause Process

Pause execution completely:

```bash id="’wini634"
kill -STOP PID
```

Process freezes.

Cannot ignore signal.

---

# 12. SIGCONT — Resume Process

Continue paused process:

```bash id="’wini635"
kill -CONT PID
```

---

# 13. Real Experiment

Start process:

```bash id="’wini636"
yes > /dev/null
```

Find PID:

```bash id="’wini637"
pgrep yes
```

Pause:

```bash id="’wini638"
kill -STOP PID
```

Check:

```bash id="’wini639"
ps -l -p PID
```

State becomes:

```text id="’wini640"
T
```

meaning stopped.

Resume:

```bash id="’wini641"
kill -CONT PID
```

---

# 14. SIGHUP

Historically:

```text id="’wini642"
terminal disconnected
```

Today often means:

```text id="’wini643"
reload configuration
```

Example:

```bash id="’wini644"
sudo kill -HUP nginx_pid
```

Many daemons reload configs without restarting.

---

# 15. Using `pkill`

Instead of PID:

```bash id="’wini645"
pkill yes
```

or:

```bash id="’wini646"
pkill -9 yes
```

Much easier.

---

# 16. Using `killall`

Example:

```bash id="’wini647"
killall yes
```

Signals all matching processes.

---

# 17. Signals and Process States

Signals can cause:

| Signal  | Result          |
| ------- | --------------- |
| SIGSTOP | stopped         |
| SIGCONT | running         |
| SIGTERM | terminating     |
| SIGKILL | immediate death |

---

# 18. Which Signals Can Be Ignored?

Processes may catch/ignore many signals.

BUT:

| Signal  | Ignorable? |
| ------- | ---------- |
| SIGTERM | yes        |
| SIGINT  | yes        |
| SIGKILL | no         |
| SIGSTOP | no         |

Kernel enforces SIGKILL and SIGSTOP.

---

# 19. Signals in Programming

Programs can register handlers.

Example in C:

```c id="07a9of"
signal(SIGINT, handler);
```

Java, Python, Node.js also support signal handling.

Very important for backend servers.

---

# 20. Real Backend Example

Suppose Spring Boot app receives:

```text id="’wini648"
SIGTERM
```

Kubernetes sends this during shutdown.

Application should:

* finish requests
* close DB connections
* flush logs
* exit cleanly

---

# 21. Docker and Signals

Docker containers heavily rely on signals.

Example:

```bash id="’wini649"
docker stop container
```

Usually sends:

```text id="’wini650"
SIGTERM
```

then later:

```text id="’wini651"
SIGKILL
```

if app refuses to exit.

---

# 22. Systemd and Signals

`systemd` manages services mostly through signals.

Example:

```bash id="’wini652"
sudo systemctl stop nginx
```

internally uses signals.

---

# 23. Useful Monitoring

Watch signals indirectly using:

```bash id="’wini653"
ps -l
```

State changes:

| State | Meaning  |
| ----- | -------- |
| `R`   | running  |
| `S`   | sleeping |
| `T`   | stopped  |
| `Z`   | zombie   |

---

# 24. Important Mental Model

```text id="’wini654"
signals are lightweight process-control messages
```

They are one of the core Unix communication mechanisms.
