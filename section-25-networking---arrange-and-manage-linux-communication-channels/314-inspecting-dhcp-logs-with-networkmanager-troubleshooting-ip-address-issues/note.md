# 314. Inspecting DHCP Logs with `NetworkManager`

## Why do we need this?

When your computer cannot obtain an IP address automatically, you may experience problems such as:

* No internet connection
* "Connected" Wi-Fi but websites do not open
* Ethernet cable connected but no network access
* IP address changes unexpectedly
* DNS problems

Most Linux desktop distributions (Ubuntu, Fedora, Mint, etc.) use **NetworkManager** to manage network interfaces and communicate with DHCP servers.

When a problem occurs, the first place to investigate is the **NetworkManager logs**.

---

# Viewing NetworkManager Logs

```bash
journalctl -u NetworkManager
```

### Explanation

| Part           | Meaning                       |
| -------------- | ----------------------------- |
| journalctl     | Read systemd logs             |
| -u             | Filter by unit                |
| NetworkManager | Show only NetworkManager logs |

This command displays all logs generated by NetworkManager.

Example:

```text
May 26 10:12:10 host NetworkManager[742]:
device (wlp2s0): state change: disconnected -> prepare

May 26 10:12:11 host NetworkManager[742]:
dhcp4 (wlp2s0): activation: beginning transaction

May 26 10:12:13 host NetworkManager[742]:
dhcp4 (wlp2s0): state changed new lease

May 26 10:12:13 host NetworkManager[742]:
device (wlp2s0): state change: ip-config -> activated
```

This means:

1. Wi-Fi disconnected
2. NetworkManager started DHCP negotiation
3. DHCP server provided an IP address
4. Connection became active

---

# Show Logs From Current Boot Only

```bash
sudo journalctl -b -u NetworkManager
```

### Why use `-b`?

Without `-b`:

```bash
journalctl -u NetworkManager
```

you may see logs from:

* today
* yesterday
* last week

and thousands of lines.

With:

```bash
journalctl -b -u NetworkManager
```

you only see logs from the current boot session.

Much easier for troubleshooting.

---

# Useful Filters

### Show latest logs

```bash
journalctl -u NetworkManager -n 50
```

Shows only the last 50 lines.

---

### Follow logs live

Similar to:

```bash
tail -f
```

Use:

```bash
journalctl -fu NetworkManager
```

Now you can:

1. Open Terminal 1

```bash
journalctl -fu NetworkManager
```

2. Disconnect Wi-Fi
3. Reconnect Wi-Fi

You will immediately see DHCP events appear in real time.

Very useful during troubleshooting.

---

# Searching for DHCP Messages

NetworkManager logs contain many messages.

To focus on DHCP:

```bash
journalctl -u NetworkManager | grep -i dhcp
```

Example output:

```text
dhcp4 (wlp2s0): activation: beginning transaction
dhcp4 (wlp2s0): state changed new lease
dhcp4 (wlp2s0): renewal succeeded
```

---

# Common DHCP Events

## 1. DHCP Request Started

```text
dhcp4 (enp0s3): activation: beginning transaction
```

Meaning:

NetworkManager is asking a DHCP server for an IP address.

---

## 2. Lease Obtained

```text
dhcp4 (enp0s3): state changed new lease
```

Meaning:

The DHCP server successfully assigned:

* IP address
* subnet mask
* gateway
* DNS server

---

## 3. Lease Renewal

```text
dhcp4 (enp0s3): renewal succeeded
```

Meaning:

The existing IP address was renewed successfully.

No connectivity issue exists.

---

## 4. DHCP Failure

```text
dhcp4 (enp0s3): request timed out
```

Meaning:

No DHCP server replied.

Possible causes:

* Router down
* Cable unplugged
* Wi-Fi disconnected
* DHCP service disabled on router
* Firewall issue

---

# Real Troubleshooting Scenario

Suppose:

```bash
ip a
```

shows:

```text
enp0s3:
inet6 ...
```

but no:

```text
inet 192.168.x.x
```

This means IPv4 was not assigned.

Check logs:

```bash
sudo journalctl -b -u NetworkManager
```

Look for:

```text
dhcp4: request timed out
```

Now you know:

The problem is DHCP.

Not DNS.
Not browser.
Not application.

---

# Check Your System

Since you are using Ubuntu, try:

```bash
systemctl is-active NetworkManager
```

If active:

```bash
sudo journalctl -b -u NetworkManager -n 30
```

Then identify:

* interface name (`wlp...`, `enp...`)
* DHCP messages
* activation messages

### Interview Question

**Q:** A Linux machine connected to Wi-Fi cannot access the internet and has no IPv4 address. Which log would you inspect first?

**A:** NetworkManager logs:

```bash
sudo journalctl -b -u NetworkManager
```

Then search for DHCP-related errors such as:

```text
request timed out
no lease obtained
```

to determine whether the machine failed to obtain an IP address from the DHCP server.
